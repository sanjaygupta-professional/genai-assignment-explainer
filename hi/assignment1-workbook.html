Job #5 है "Secondary School Teacher." इसे "DBA Gen AI Professor" में customize करने से आपको एक richer, ज़्यादा specialized KB मिलता है — research papers, textbooks, और course materials बिल्कुल वही structured text corpus है जहाँ RAG सबसे अच्छा काम करता है। इससे आप genuine subject-matter authority के साथ लिख सकते हैं।
Context: यह customization strong क्यों है?

एक secondary school teacher की KB में general curricula, lesson plans, और textbooks हो सकती हैं। एक DBA Gen AI Professor की KB कहीं ज़्यादा rich है:

  • LLMs, RAG, और AI ethics पर peer-reviewed research papers
  • Machine learning और NLP पर academic textbooks
  • Course syllabi, assignment rubrics, और grading schemas
  • पिछले cohorts के student FAQ archives
  • Conference proceedings (NeurIPS, ICML, ACL)

हर document type का एक clear retrieval use case है, जो आपकी RAG story को airtight बनाता है।

✎ आपका काम — Section 1

Job #5: Secondary School Teacher → DBA Gen AI Professor

Customization: Original job है "Secondary School Teacher — Prepare how to teach a new lesson." मैंने इसे DBA (Doctor of Business Administration) professor में adapt किया है जो Generative AI पढ़ाता है। Underlying task वही है — lesson content तैयार करना — लेकिन domain postgraduate AI education में shift हो जाता है, जहाँ source material denser है और तेज़ी से बदलता है।

GenAI से इस job को फ़ायदा क्यों: Gen AI पढ़ाने का मतलब है कि हर हफ़्ते नए papers आते हैं, और एक ही lecture के लिए दर्ज़नों sources चाहिए। Up-to-date रहना genuinely मुश्किल है। एक RAG assistant जो course knowledge base को index करता है, मुझे demand पर सही material retrieve करने देता है और structured draft responses देता है, जो prep time काफ़ी कम कर देता है। बड़ा फ़ायदा यह है कि यह sources cite करता है — तो मैं किसी भी claim को original paper या lecture note तक trace कर सकता हूँ, LLM की memory पर भरोसा करने की ज़रूरत नहीं।

Q2: Can / Cannot Analysis

GenAI CAN: कुछ भी जो "सही passage ढूँढो और explain करो" तक सीमित हो। Retrieval, summarization, quiz generation, lesson planning — अगर जवाब knowledge base में कहीं है, तो GenAI उसे तेज़ी और reliably surface कर सकता है।

GenAI CANNOT: यह judge करना कि student का argument original है या नहीं, class discussion बिगड़ने पर room read करना, या struggling student को extension देने का decision लेना। इनके लिए empathy और professional judgment चाहिए जो कोई retrieval pipeline approximate नहीं कर सकती।

Chunking Strategy

Markdown documents: Heading-aware splitting। पहले H1-H3 headings पर split, फिर अगर section 800 characters से ज़्यादा हो तो paragraph पर, फिर sentence boundary पर। हर chunk अपनी parent heading inherit करता है context के लिए।

PDF documents: Sliding window — 800-character chunks, 150-character overlap, sentence boundaries पर snap (window end से पहले last ". ")। Mid-word splits prevent होते हैं।

Context injection: हर chunk को embedding से पहले [Source: type:filename | Title] prefix किया जाता है। इस तरह vector representation में source context include होता है, सिर्फ़ raw text नहीं।

Q4: Full RAG Pipeline — 8-Stage Architecture

Stage 1 — Document Ingestion

Source formats: PDF (papers), DOCX (syllabus), JSON (FAQ)। Tools: PDF extraction के लिए pypdf2, DOCX के लिए python-docx, custom JSON parser। Output: source metadata attached raw text strings।

Stage 2 — Chunking

Strategy: recursive character splitter, 800-character chunks, 150-character overlap। Papers paragraph boundary पर chunked। FAQ individual Q&A pairs के रूप में chunked। Rationale: 500 tokens gemini-2.0-flash context में अच्छे से fit होते हैं और per chunk enough context देते हैं।

Stage 3 — Embedding

Model: gemini-embedding-001 (Google Gemini, 3072 dimensions)। हर chunk Google Gemini API से embed। Cost: free tier (1,500 RPD तक)। Rationale: strong semantic retrieval quality, ~500-document KB के लिए low cost।

Stage 4 — Vector Store

Platform: JSON cosine-similarity store (fallback) (या local FAISS)। Index: cosine similarity। doc_type, year, course_relevance के लिए metadata filters enabled। Scoped retrieval के लिए per course module namespace।

Stage 5 — Query Processing और Retrieval

Student query same model से embed। Cosine similarity से top-k=5 chunks retrieve। Optional: hybrid search (dense + BM25 keyword)। Precision के लिए cross-encoder re-ranking। अगर query specific module target करे तो metadata filter apply।

Stage 6 — Context Augmentation

Retrieved chunks context window में concatenate। Format: [Source: Lewis et al. 2020, chunk 3] <text>। System prompt model को sources cite करने का instruction देता है। Total context budget: 4,000 tokens (5 chunks × ~500 tokens + system prompt + query)।

Stage 7 — Generation

LLM: Google AI Studio से gemini-2.0-flash। Temperature: 0.2 (factual task)। Max tokens: 600। Model को instruction कि context से ही answer करे और KB insufficient हो तो flag करे।

Stage 8 — Output और Evaluation

Response में source chunks की citations include। Evaluation: (a) Faithfulness — क्या answer retrieved passages से match करता है (no hallucination)? (b) Answer Relevance — क्या answer query address करता है? (c) Context Precision — क्या सही chunks retrieve हुए? Tools: RAGAS framework या manual spot-check।

✎ आपका काम — Section 5 (Criterion 2, 5 अंक)

8-Stage RAG Pipeline (Actual Implementation)

  1. Document Loading: loader.ts markdown (Bun.file().text()) और PDFs (pdf-parse with Buffer.from(arrayBuffer)) read करता है। Metadata extract: session number, title, source type।
  2. Chunking: chunker.ts — lecture notes के लिए markdown-aware splitting (heading → paragraph → sentence hierarchy); PDFs के लिए sliding window (800/150)। Context prefix inject होता है।
  3. Embedding: embedder.ts — Gemini gemini-embedding-001 (3072-dim vectors)। 20/batch batched, 2s rate-limit delays। chunks के लिए taskType: RETRIEVAL_DOCUMENT, queries के लिए RETRIEVAL_QUERY। Exponential backoff (1s, 2s, 4s) के साथ retry।
  4. Storage: fallback.ts — cosine similarity के साथ JSON-persisted in-memory store। 78MB store file (1,260 chunks × 3072 floats)। Server startup पर load।
  5. Query Embedding: User query same Gemini model से taskType=RETRIEVAL_QUERY के साथ embed।
  6. Retrieval: retriever.ts — 2× oversampling (16 fetch, 8 return)। MMR-lite diversity reranking: same-document results penalize (−30%) और over-represented source types (−15% अगर same type से ≥3)।
  7. Generation: generator.ts — Gemini gemini-2.0-flash (temp=0.4, max 2048 tokens)। DBA Professor persona। 5 modes (explain, teaching-plan, quiz-questions, connect, research-angle)। Score < 0.70 पर relevance gate clean refusal return करता है।
  8. Response Assembly: Generated text से [N] citations extract, retrieved sources से match। Top-3 retrieval scores से confidence estimate।

RAG Optimization Strategies

Strategy 1: Query Rewriting

Student query embed करने से पहले, एक lightweight LLM call use करके उसे clearer retrieval-optimized form में rewrite करें। Example: "HyDE क्या है?" → "Hypothetical Document Embeddings (HyDE) explain करें और बताएँ कि ये RAG retrieval कैसे improve करते हैं।" यह terse या ambiguous student phrasing से होने वाली retrieval failures prevent करता है।

Strategy 2: Cross-Encoder Re-Ranking

Cosine similarity से top-20 chunks retrieve करें, फिर cross-encoder (जैसे ms-marco-MiniLM-L-6-v2) से re-rank करें जो query + chunk jointly consider करता है। Re-ranking के बाद top-5 return करें। यह nuanced academic queries के लिए precision significantly improve करता है।

Strategy 3: Metadata Pre-Filtering

Queries को classifier से route करके intent detect करें: "assignment question" vs. "technical concept" vs. "paper recommendation।" Accordingly metadata filters apply करें (जैसे assignment queries के लिए doc_type=syllabus restrict)। Retrieved context में noise कम होता है।

Optimization strategies

Testing के दौरान आई issues के basis पर मैंने चार practical optimizations build किए:

  • अगर total prompt 30K characters से exceed करे, तो system lowest-scored results drop कर देता है जब तक fit न हो जाए। यह broad queries के साथ आया जो बहुत ज़्यादा chunks pull कर रही थीं।
  • Score < 0.70 पर relevance gate LLM call किए बिना refusal return करता है। Off-topic queries पर API cost बचता है और KB में कुछ relevant न होने पर hallucinated answers avoid होते हैं।
  • Confidence avg(top-3 retrieval scores) से calculate होती है citation boost के साथ। 0.30 से नीचे कुछ भी 0.20 पर cap हो जाता है — weak retrievals पर UI false confidence display न करे।
  • हर chunk में [Source: type | title] prefix include है, जो implicitly LLM को citation format सिखाता है। Citation behavior के लिए few-shot examples की ज़रूरत नहीं।

Rubric Reminder
  • यह criterion 20% worth है और सबसे commonly underweighted। एक basic ChatGPT conversation भी count होती है — skip मत कीजिए।
  • कम से कम 3 interactions दिखाइए: एक successful retrieval, एक failure case, और एक जो आपका system prompt action में दिखाए।
  • Screenshots या pasted conversation logs include कीजिए। उन्हें annotate कीजिए: क्या अच्छा चला, क्या नहीं, और क्या improve करेंगे।
  • अगर ChatGPT की बजाय Google AI Studio use करें, तो endpoint और model note कीजिए।
इस assignment के लिए full production RAG deployment मत करिए। एक simple ChatGPT session जहाँ आप अपना system prompt + relevant paper excerpts context के रूप में paste करें, पूरी तरह sufficient है। Point interaction pattern demonstrate करना है, engineering perfection नहीं।
Suggested Tryout Protocol

Step 1: अपना mini-KB context तैयार करें

अपने sample documents से 2–3 passages copy करें (हर एक 150–200 words)। यह simulate करता है कि आपका retriever क्या return करेगा।

Step 2: ChatGPT या Google AI Studio खोलें

नई conversation start करें। पहले अपना system prompt paste करें, फिर context passages, फिर अपने student queries pose करें।

Step 3: 3 test interactions run करें

  • Test A: एक query जो आपकी KB अच्छे से handle करती है (जैसे "RAG क्या है?")। Success case दिखाता है।
  • Test B: एक query जो आपकी KB scope के बाहर है (जैसे "Microsoft का stock price क्या है?")। Graceful failure दिखाता है — model को कहना चाहिए "KB में नहीं है।"
  • Test C: एक multi-hop question जिसमें 2 documents चाहिए (जैसे "हमारे professor assistant use case के लिए BM25 vs. dense retrieval compare करो")। Synthesis capability दिखाता है।

Step 4: Screenshot और annotate करें

तीनों conversations के screenshots लीजिए। अपने write-up में हर एक को briefly annotate कीजिए: model ने क्या अच्छा किया? क्या गलत? v2 में क्या fix करेंगे?
