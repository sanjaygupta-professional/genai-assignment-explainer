अध्याय 1

भारत में दिव्यांग लाभ ढूंढना

भारत RPwD Act 2016 के तहत 21 प्रकार की दिव्यांगताओं को मान्यता देता है। केंद्र और राज्य स्तर पर सैकड़ों सरकारी योजनाएं हैं — हर एक के लिए दिव्यांगता प्रकार, उम्र, आय और भूगोल के अलग-अलग eligibility criteria हैं। Cerebral palsy वाले बच्चे के परिवार को सही योजनाएं खोजने के लिए ऐसी भाषा में लिखे गए बहुत सारे सरकारी PDFs को पढ़ना पड़ता है जो शायद उन्हें पूरी तरह समझ न आए।

कर्नाटक में एक माँ पूछती हैं: "मेरी बेटी 12 साल की है, उसे locomotor disability है। हमारी आय 1.2 लाख रुपये सालाना है। उसे कौन सी योजनाएं मिल सकती हैं?" आज इसका जवाब देने के लिए 6+ सरकारी PDFs पढ़ने, eligibility matrices समझने और criteria को manually cross-reference करने की ज़रूरत है। ज़्यादातर परिवार हार मान लेते हैं।

सामान्य RAG क्यों काम नहीं करता

एक pure RAG system document chunks को embed करता है और semantic similarity से search करता है। यह open-ended सवालों के लिए ठीक काम करता है लेकिन multiple conjunctive filters वाले structured eligibility queries पर fail हो जाता है:

Vector Search अच्छा काम करता है

  • "दिव्यांग योजनाएं कौन-कौन सी हैं?"
  • "Niramaya insurance कैसे काम करता है?"
  • "UDID card प्रक्रिया समझाइए"

Vector Search यहाँ फेल होता है

  • "Locomotor, उम्र 12, कर्नाटक, आय < 1.5L के लिए योजनाएं"
  • "Autism और cerebral palsy दोनों cover करने वाली योजनाएं"
  • "सिर्फ आधार + disability cert चाहिए वाली सभी योजनाएं"
अध्याय 2

Hybrid Approach

मूल विचार: दो complementary retrieval paths इस्तेमाल करो, हर एक वो करे जिसमें वो best है, फिर results को merge करो।

अकेला कोई भी path काफ़ी नहीं है। Vectors conjunctive filtering नहीं कर सकते ("locomotor AND उम्र 12 AND कर्नाटक AND आय < 1.5L")। Graphs semantic similarity नहीं कर सकते ("ऐसे बच्चों के लिए योजनाएं बताओ जो चल नहीं सकते")। दोनों मिलकर information खोजने के दोनों तरीके cover करते हैं।

Design Choices & Trade-offs

फ़ैसलाचुनावक्यों
Embedding modelGemini Embedding 2Native PDF embedding, बहुभाषी (हिंदी), Matryoshka dims, $0.25/M tokens
Embedding dims768 (3072 नहीं)Matryoshka support: 4x memory बचत, ~2% quality loss, PoC scale के लिए काफ़ी
Vector DBQdrant (file-persisted)Docker या server नहीं चाहिए। बस pip install। Production-ready API।
Graph DBKuzu (embedded)Neo4j जैसा Cypher (skills transfer)। pip install kuzu। Docker/Java नहीं चाहिए।
RetrievalHybrid (KG + Vector)KG structured eligibility filtering करता है। Vectors semantic similarity करते हैं।
Chunking5 पृष्ठ, 1-पृष्ठ overlapGemini Embedding 2 की ~6-पृष्ठ limit में fit। Overlap boundary context preserve करता है।
Query parsingGemini Flash extractionKG Cypher queries के लिए zero-shot structured extraction। Training data ज़रूरत नहीं।
Dataसिर्फ़ असली gov.inअसली परिवारों के लिए असली दस्तावेज़। कोई synthetic data नहीं। भरोसा और विश्वसनीयता।
Kuzu vs Neo4j: Original design में Neo4j था। इस PoC के लिए हमने Kuzu इस्तेमाल किया — वही Cypher, pip से install, कोई server नहीं। Production में Neo4j Aura (free tier: 200K nodes) पर switch करो। Queries में zero code changes।
अध्याय 5

Knowledge Graph

KG सरकारी PDFs से निकाला गया structured eligibility metadata encode करता है। यह वो जवाब देता है जो vector search नहीं दे सकता: "कौन सी योजनाएं locomotor disability cover करती हैं, कर्नाटक में उपलब्ध हैं, उम्र 12 के लिए, आय 1.5 लाख से कम?"

Cypher Query का उदाहरण

-- Find schemes for a 12-year-old with locomotor disability in Karnataka MATCH (s:Scheme)-[:COVERS]->(d:DisabilityCategory), (s)-[:AVAILABLE_IN]->(st:State), (s)-[:FOR_AGE_GROUP]->(ag:AgeGroup) WHERE d.name CONTAINS 'locomotor' AND (st.name CONTAINS 'Karnataka' OR st.id = 'all_india') AND ag.min_age <= 12 AND ag.max_age >= 12 RETURN s.name, s.benefit_type, s.benefit_value_inr
मेरी बेटी 12 साल की है, उसे locomotor disability है। हम कर्नाटक में रहते हैं और हमारी पारिवारिक आय 1.2 लाख रुपये सालाना है।
ADIP Scheme Pre-Matric Scholarship DDRS SIPDA
4 योजनाएं match हुईं — सभी 4 criteria (दिव्यांगता + उम्र + राज्य + आय) एक ही Cypher query से resolve हुए

रोडमैप: PoC से Production तक

पूरा हुआ

6 documents, KG में 8 schemes, text-mode embeddings, CLI + REPL, 5 verified demo queries।

असली परिवारों के लिए WhatsApp/Telegram bot

Production
Neo4j Aura + Qdrant Cloud पर migrate करना
Neo4j Aura free tier (200K nodes)। Qdrant Cloud managed hosting। Auth, rate limiting, monitoring।
Research
Agentic document update pipeline
Agent gov.in feeds monitor करता है, योजना changes detect करता है, affected chunks re-embed करता है, KG nodes automatically update करता है।
