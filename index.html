1 Assignment Overview

This assignment asks you to conceptually design a RAG-based GenAI solution for one of 10 real-world jobs. You're not building production software — you're demonstrating that you understand how to architect a GenAI system that uses domain-specific knowledge to help new employees do their job better.

Format Requirements

  • Length: 1–7 A4 pages of written content + up to 3 pages of screenshots/code. Content after page 10 is ignored.
  • Style: “A lucid note” — clear, structured prose (not slides or bullet dumps).
  • Assumptions: You're free to make reasonable assumptions about KB document formats, sample queries, tool choices, etc. State them explicitly.
  • Language: English.

Score Distribution

Five criteria, each worth 5 marks (20% of total 25):

  1. Detailing of KB and Sample Query format
  2. Overall GenAI solution design
  3. Prompts and RAG effectiveness enhancement
  4. Identification of solution limitations
  5. Efforts to try out the solution (Azure OpenAI / ChatGPT / other platform)
The 5th criterion — actually trying your solution — is worth the same 20% as the architecture design. Don't treat it as optional! Even a basic ChatGPT conversation demonstrating your approach counts. This is the most commonly underweighted criterion.

3 The 5 Questions You Must Answer

Q1: How much can GenAI help? (Fully / Mostly / Partly / Hardly)

You must pick one: (a) Fully 100%, (b) Mostly 80%+, (c) Partly 40%+, or (d) Hardly <20%.

How to Justify Your Choice

  • Decompose the task into sub-tasks. For each, assess: Can GenAI do it? How well?
  • Identify the human-only parts: judgment calls, ethical decisions, physical actions, real-time social cues.
  • Be specific: “GenAI can retrieve similar cases and suggest search terms (70% of the work), but a human must verify legal applicability and make the final case selection (30%).”
Don't pick “Fully” unless you can truly defend 100% automation. Most jobs need human oversight. “Mostly” is the safe sweet spot for most choices — it shows you understand GenAI's power while acknowledging real-world limits.
Legal Assistant — Finding similar cases: “Mostly (80%+). GenAI with RAG can search through past search logs, identify patterns in successful queries, suggest relevant search terms, and even rank case similarity. However, a human must verify legal relevance, check for jurisdictional applicability, and validate that returned cases are currently good law.”
Q2: What can GenAI do vs NOT do for this task?

Create a clear two-column analysis:

GenAI CAN DoGenAI CANNOT Do
Retrieve relevant KB documents based on semantic similarity Exercise professional judgment or ethical reasoning
Synthesize information from multiple sources into coherent responses Guarantee factual accuracy without human verification
Identify patterns across historical data Handle novel situations with no KB precedent
Suggest next steps based on past expert behavior Understand real-time contextual nuances (tone, urgency, politics)
The strongest answers connect each “CANNOT” item to a specific mitigation strategy. For example: “GenAI cannot guarantee accuracy → we add a confidence score and human-in-the-loop review for responses below 0.8 threshold.”
Q3: Build approach — From scratch, fine-tuning, prompting, or RAG?

The assignment strongly hints at RAG as the expected answer — it's in the title and problem statement. But you should still justify why RAG over the alternatives:

ApproachWhen It WorksWhy Not Here
From scratch Unique language/domain, massive data, unlimited budget Prohibitive cost, needs millions of examples, reinvents solved problems
Fine-tuning Narrow domain style, consistent output format needed KB updates require retraining; doesn't scale well with evolving knowledge
Prompting only General knowledge tasks, no proprietary data needed Can't access KB; limited by context window; no domain-specific knowledge
RAG Domain-specific KB, needs current data, explainability important This is the answer — KB is the centerpiece of the solution
Even though RAG is expected, mention that you might combine approaches: RAG for retrieval + prompt engineering for response quality + potential fine-tuning for domain-specific language. This shows sophistication.
Q4: Conceptual RAG architecture design

This is the core of your assignment — see Section 6: RAG Architecture Primer for the full visual guide. Your design should cover:

  1. Document ingestion: How KB documents are chunked, embedded, and indexed
  2. Query pipeline: How user queries flow through embedding → retrieval → context injection → LLM generation
  3. Tool choices: Specific embedding models, vector DBs, LLMs, orchestration frameworks
  4. Prompt design: System prompts, few-shot examples, output format instructions
  5. Evaluation method: How you'd measure if the solution actually works
The rubric for Criterion 2 explicitly says: “the method of estimating the success of the approach is also clearly stated.” Many students describe the architecture but forget to explain how they'd evaluate it. Include metrics like retrieval precision, answer relevance scores, or user satisfaction ratings.
Q5: Limitations and risks

The assignment specifically mentions TCO and response time. Cover these categories:

  • Cost (TCO): Embedding computation, vector DB hosting, LLM API costs per query, KB maintenance
  • Performance: Latency (embedding + retrieval + generation), throughput for concurrent users
  • Quality risks: Hallucination, retrieval failures, outdated KB, bias in historical data
  • Operational risks: Data privacy, KB curation effort, model deprecation, vendor lock-in
  • Domain-specific risks: Whatever is specific to your chosen job (e.g., legal liability for Legal Assistant)
Don't just list risks — propose mitigations for each. “Hallucination risk → mitigated by including source citations in every response and requiring human review for high-stakes decisions.” This turns a weakness into a strength in your answer.

This is Criterion 5 (20%). Here are three approaches ordered by impressiveness:

Option A: LangChain/LlamaIndex Demo (Best — targets "Significant" rating)

# Minimal LangChain RAG in ~20 lines from langchain.document_loaders import JSONLoader from langchain.text_splitter import RecursiveCharacterTextSplitter from langchain.embeddings import OpenAIEmbeddings from langchain.vectorstores import Chroma from langchain.chat_models import ChatOpenAI from langchain.chains import RetrievalQA # Load and chunk your KB documents docs = JSONLoader("kb_samples.json").load() chunks = RecursiveCharacterTextSplitter( chunk_size=500, chunk_overlap=100 ).split_documents(docs) # Create vector store and retrieval chain vectorstore = Chroma.from_documents(chunks, OpenAIEmbeddings()) qa_chain = RetrievalQA.from_chain_type( llm=ChatOpenAI(model="gpt-4o-mini"), retriever=vectorstore.as_retriever(search_kwargs={"k": 5}), ) # Test with your sample queries result = qa_chain.invoke("What parts of claims like this should be rejected?") print(result)

6 RAG Architecture Primer

This section gives you the technical foundation to design your RAG pipeline with confidence. Use this as the basis for your architecture diagram in the assignment.

Document Ingestion Pipeline

Key Decisions for Ingestion

  • Chunking strategy: Recursive character splitting preserves paragraph boundaries. Use 500-1000 tokens per chunk with 100-token overlap to avoid losing context at boundaries.
  • Metadata: Store document-level metadata (date, category, author) alongside each chunk for filtered retrieval.
  • Embedding model: OpenAI's text-embedding-3-small (1536 dimensions) offers strong quality at $0.02/million tokens.

Query Pipeline

RAG Enhancement Strategies

Mention 2-3 of these in your assignment to demonstrate depth (Criterion 3):

1. Hybrid Search (Keyword + Semantic)

Combine BM25 (keyword matching) with vector similarity for better retrieval. Useful when queries contain specific IDs, names, or legal terms that pure semantic search might miss.

2. Query Expansion

Use the LLM to expand the user's query before retrieval: “Find related cases” → “Find related cases involving patent infringement, software claims, prior art challenges.”

3. Re-Ranking

After initial vector search returns top-20 results, use a cross-encoder model to re-rank them for relevance. Returns more precise top-5 to the LLM, improving answer quality.

4. Metadata Filtering

Filter retrieval by metadata (date range, category, jurisdiction) before or during vector search. Reduces noise and improves relevance.

Prompt Engineering for RAG

Your system prompt should include these elements:

# System Prompt Template for RAG ROLE: You are a [job title] assistant helping new employees at [company type]. Your role is to [specific task]. CONTEXT RULES: - Use ONLY the provided context to answer questions - If the context doesn't contain relevant information, say so clearly - NEVER fabricate information not present in the context - Cite specific document IDs when referencing KB content OUTPUT FORMAT: - Begin with a direct answer to the query - Support with 2-3 specific examples from the KB - Include confidence level (high/medium/low) - End with suggested next steps for the employee CONSTRAINTS: - [Domain-specific guardrails, e.g., "Do not provide legal advice"] - [Escalation criteria, e.g., "For queries involving amounts over $X, recommend supervisor review"]
Include your actual system prompt in the assignment — it's tangible evidence of prompt engineering skill. Even a simple, well-structured prompt scores higher than vague descriptions of “we would use appropriate prompting.”
